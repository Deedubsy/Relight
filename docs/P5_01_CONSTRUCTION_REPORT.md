## Implemented behaviour

Factory player controls now submit ordinary sim commands through the session dispatcher. Placement, pickup, rotation, recipes, chest transfers, feeding, mining, crafting, light repair and material delivery use the command boundary; queued earlier inputs are flushed in order, each action is logged once, and construction works while paused. Existing campaign restoration/defence/freight commands remain commands. Historical developer/test hooks are explicitly separate from player controls and retain their old helper interfaces.

Holding the belt tool and dragging previews a contiguous path, filling skipped pointer tiles and facing belts through corners. Release commits one atomic construction group; insufficient materials, occupied tiles, unavailable construction or reach failure refuse the whole path. Backtracking trims the preview. Escape, leaving the canvas, changing tools or switching views cancels it. The path limit is 128 tiles, with x-then-y interpolation for a diagonal pointer jump; the last belt follows the previous segment, or the selected rotation for a single tile. These are provisional implementation defaults, not balance approvals.

Ctrl+Z and Ctrl+Y/Ctrl+Shift+Z, plus build-menu buttons, undo/redo the last construction group. The saved history retains at most 50 groups. This compensates construction using current stock and reach: packing recovers the machine and its current contents, rebuilding uses a carried machine first or its normal raw-material price, and recovered contents stay in pockets. Rotation and machine settings are preserved. Machine identities survive rebuilds so adjacent placement/rotation/pickup entries still work. Time, production, discovery, repairs and combat never rewind.

Changes to a machine's identity, location, facing or settings, damage, active repairs, full pockets, occupied rebuild sites and lost reach can refuse undo/redo without partial effects. Packing also refuses unfinished assembler recipes, fractional legacy contents and loose turret rounds that would overflow the ammunition buffer. The player can finish the recipe or free capacity and retry. The history does not restore production progress, fuel already spent, transported goods or a moving tram's earlier location. Existing freight interruption and cargo rules continue to apply.

An optional version-1 construction-history field is validated on load; profiles that have not used construction history keep their earlier initial state. Saves retain history and complete command logs. Replay now includes already-committed commands at the final tick without advancing the world: the browser test exposed that the former replay loop omitted paused final-tick actions. Existing bare snapshots still lack a complete fresh-start replay log; no cross-version gameplay-replay promise is added.

The hotbar and build menu reference one catalogue, with machine purpose, current material cost, carried counts and sim-owned unlock reasons. Input handlers share a binding table. The provisional English factory presentation table supplies catalogue purposes, construction/help labels and displayed bindings; established simulation refusal/status descriptions remain with their sim queries. This is factory UI groundwork, not translated content or completed game-wide localisation. D-SA-2 human sign-off remains at phase exit. Future machine/status UI must reuse these tables and the existing sim queries.

Opening pockets or the build menu scrolls it into view. Picking a tool or closing menus returns the narrow layout to the canvas. At the stacked viewport, the goal overlay scrolls with the world rather than covering the menu. Ctrl shortcuts and focused text inputs do not move the engineer.
