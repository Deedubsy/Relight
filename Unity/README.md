## What this package is

Phase A produced a complete, source-referenced description of the reference game and a plan to port it. Every fact carries a status label so the port does not mistake defects for requirements or proposals for approvals:

**Implemented and retained** · **Approved but not implemented** · **Implemented but needs correction** · **Unresolved** · **Retired**

Numbers are tagged **current** (what the code does today), **approved** (explicitly confirmed by the owner) or **provisional** (chosen for the checkpoint and open to change).

## Reading guide for a task session

Do not reread the whole package (about 61,000 words) each session. A session that picks up one task reads, in this order:

1. This README (status table, working agreement, rules).
2. The selected task row in [Docs/TASKS.md](Docs/TASKS.md), the rows it depends on, and TASKS.md §6–§7 (dependency summary and residue).
3. Every decision row the task row names (`U-D` / `U-M` / `U-P` / `U-Q` in [Docs/DECISIONS.md](Docs/DECISIONS.md)) and the specialist sections the task row cites (a `§` reference into GAME_DESIGN, CONTENT_CATALOGUE, WORLD_AND_ASSETS, UI_AND_ONBOARDING or TECHNICAL_ARCHITECTURE).
4. The [Docs/MIGRATION_MAP.md](Docs/MIGRATION_MAP.md) rows for the system IDs (`S-xx`) the task names; they give the reference source paths.
5. Only the reference source files those rows list. Open other reference files only when a cited claim needs checking.

A session that has to choose the next task reads the rules at the top of TASKS.md and the first runnable row; it does not need the specialist documents until the task is chosen.

## Working agreement (ongoing development)

- **Coordinator.** One coordinator session handles task selection from TASKS.md, worker briefs, integration, documentation updates and final checks. The owner nominated Fable; whichever model is actually running is stated in the report rather than substituted silently.
- **Workers.** Opus workers (explicitly model-selected; a session that cannot select the model says so) receive bounded assignments with exclusive ownership of named files. A worker proposes changes to files it does not own; it never edits them. At most three workers run concurrently. No nested delegation: workers do not spawn agents.
- **One Unity Editor operator.** Only one agent at a time performs Unity Editor / MCP mutations: scene changes, asset imports, package changes, Play Mode. Other workers may edit independent source, UXML/USS or data files under coordinator control and hand off before any shared import, compilation or check.
- **Status authority.** [Docs/TASKS.md](Docs/TASKS.md) is the only owner of migration task status; one log line per status change.
- **Default verification after a meaningful player-facing change:** compile → inspect the changed feature in the Unity Editor (Play Mode or scene view, screenshot where the integration allows) → run the narrowly relevant checks for that feature → report observations and limitations plainly. Simulation tests do not substitute for checking actual UI interaction or visual combat feedback; a sim test proves the rule, not the experience.
- **Numbers.** Provisional gameplay values are starting points. Focused, documented tuning during Unity playtesting is delegated to the workers and does not need per-number approval (DECISIONS.md U-D-28, U-M-12); every change is recorded with its reason, its before/after values and its retest result. Genuine unresolved design changes still go to the owner.
- **Saving.** Manual slots plus a rotating autosave ring that never overwrites a manual slot (U-D-35). **Audio** is in scope and proportionate (U-D-33). **Input** is desktop keyboard and mouse for the initial port (U-D-42).

## Running the reference game

The reference game is the behavioural oracle for the port. Run it from the repository root, not from this folder:

```sh
npm install
npm run dev                       # Vite dev server; append ?view=world to the URL for a bare opening
npm run build -w packages/game    # production build
npm run preview -w packages/game -- --host 0.0.0.0 --port 5178 --strictPort
npm test                          # sim test suite (node:test); 318/464 passed on 2026-09-11; the 146 reported failures are not individually attributed (see MIGRATION_MAP.md §1)
npm run typecheck && npm run lint
```

Ports 5177/5179/5180/5181/5182 are frozen historical builds for comparison; 5190 is the Phaser Editor play port. Do not delete or regenerate anything under `docs/evidence/`, `packages/game/public/snapshots/` or `maps/` — they are reference data.
