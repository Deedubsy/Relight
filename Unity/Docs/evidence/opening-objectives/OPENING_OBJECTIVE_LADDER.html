Opening Objective Ladder

Forty rows, in the order the code tests them. There is no checklist and no completion flag — a row ends when its guard stops matching and control falls through to the next if. One objective is returned per call and the goal card recomputes it about every 150 ms, so rows can re-arm, and some never fire at all.

Read from the shipped sources and scene assets, not from play. Play Mode is unavailable on this machine, so nothing below was observed running — every verdict is a guard traced against CatalogueData.g.cs, OpeningBalance.cs and the authored sites in World.unity. Re-traced 2026-09-16 against the code as it stands after U-D-53, which fixed all four findings below; the findings themselves are kept as they were written.

What the trace turned up

Three dead things and one hard gate

All four were fixed on 2026-09-16 under U-D-53 (Unity/Docs/DECISIONS.md), on the owner's instruction — “Give the foundry no default. Do the rest”. The findings below are left as first written; each one says what was done. Verified by offline tests only — Play Mode has not been run on this machine.

Row 10 can never appear

“Set up the Foundry — select the Steel plates recipe” tests RecipeOf(…)?.Key != "steel-plates", but RecipeOf falls back to DefaultRecipe and the Foundry already defaults to steel-plates. Only a deliberate switch to refined-copper can bring it back.

Fixed. The Foundry, Assembler and Assembler Mk2 now ship with an empty DefaultRecipe, set in OpeningBalance.Apply — the one seam both data paths run through, so the generated catalogue and the editor .asset files are covered without either being edited.

Half of row 28 is vacuous

“Build 1 Assembler and set it to Bullets” clears the moment the machine is placed — the Assembler's DefaultRecipe is already bullet-batch, so setting it is never something the player has to do.

Fixed. With no default, “built but unset” is a state the player can sit in, so the step is now two rows: build one, then Set up the Assembler — select the Bullets recipe, pointing at the machine.

Words[0] = "no" is unreachable text

Row 34 computes more = Math.Max(0, 3 - live) inside if (live < 3), so more is always at least 1. “Build no more turrets” can never print.

Fixed. Words is { "one", "two", "three" } and the index shifts by one — a deliberate divergence from goal.ts:69, recorded as such.

Row 32 can hold the chain open forever

op.SuppliedAt moves only when Stats.TurretFed rises, and only the belt/inserter path touches that counter. Rows 33–37 sit after it, so a player who keeps hand-loading is never told to build turrets two and three.

Fixed. NoteSupply also latches on a turret with no room whose supplier still resolves, so a working line is recognised even when the player leaves it nothing to deliver. The walk is gated on a real producer and on production having happened, so a hand load still cannot fake it.
