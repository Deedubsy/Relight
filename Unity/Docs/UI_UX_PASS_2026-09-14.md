# Relight Unity UI/UX pass — 14 September 2026

Owner-authorised implementation, following the Fable correction pass and the earlier Codex interaction repair. Target: desktop keyboard/mouse, Unity **6000.6.0f1**, project `Unity/Relight`. This report describes this pass only; migration status lives in [TASKS.md](TASKS.md). C-ACC remains an owner playtest.

## Reference comparison and resulting decisions

Reference material was public manuals and screenshots, not hands-on play of the other games. Exact patches are stated only where identified by the source. No external artwork was copied into Relight.

## What changed and why

- **Persistent action dock:** useful construction defaults on new games, two empty slots, icons, quantities, selection and live bindings. Construction counts mean packed items plus currently affordable builds; weapon counts mean loaded bullets. Tooltips explain the distinction. Existing saved layouts are retained; defaults grant no items. Right-click clears a shortcut. Assigning an already-present tool swaps its previous slot.
- **World hover and mining:** the pointer resolves the visible tile independently of the selected tool. Placed machine footprints take precedence over buried resources. Geometry visibility prevents resource identification through solid buildings. Hover reports the target and action/reach problem; held mining stops when the pointer leaves valid salvage. Tool changes and pausing clear held actions. Normal release is communicated by the target card, without obscuring a real refusal with a second toast.
- **Achievable opening:** the material guide finds actual reachable, undepleted, unobstructed salvage. It gives a direction/distance and focuses that source with Show location. The normal 20-steel/5-copper opening reached the generator cost through walking and mining; no resource grants or cost changes were used. One compact objective remains on the HUD, with a scrollable Materials & next steps expansion.
- **Backpack and Workshop:** the persistent dock replaces the duplicate inventory quickbar. Workshop/Backpack buttons switch the drawer's focus, making recipe actions usable in a short window. Recipe icons and real ingredient names replace sparse text; spacing, wrapping and disabled states are clearer. Storage pairing clears after a load. Existing quantity, split, transfer, machine recipe/filter/priority and equipment controls remain connected to simulation commands.
- **Combat and feedback:** selecting a saved weapon shortcut equips its actual owned instance. The dock shows loaded ammo and reloading; the full HUD also shows reserve. The compact HUD keeps health separate from the objective. Notifications prioritise danger and warnings over routine confirmations, and a new session clears stale HUD notices.
- **Shared polish:** tooltips refresh live, clamp to screen edges and clear when dragging or their panel disappears. Drawers suppress conflicting world/objective overlays. Fields and scrollbars now use the shared dark palette; save text is readable. Audio controls explicitly say unavailable and are disabled when this build has no mixer.

## Focused verification

- Unity compile: passed. Existing focused EditMode classes: **MiningTests 8/8**, **TransferTests 6/6**, **HudViewModelTests 22/22**. The HUD test exposed duplicate mining notices, fixed before its successful rerun. No full EditMode/PlayMode suite was run for this pass. Required `docsync:check` and `freshness:check` could not run because `tsx` is missing in this checkout; local report links and all 14 UXML files passed direct checks. The scoped UI/documentation whitespace check passed. The broad working-tree whitespace check reports unrelated generated YAML and existing reference-file whitespace; those files were not cleaned up.
- Normal entry: Boot → title → New Game through UI controls; **20 steel / 5 copper**; actual queued Input System WASD/Tab/B/Escape and held LMB. Walked to reachable steel/copper, mined to **30/10**, selected/rotated/placed the generator through real input, spent the stock and advanced the objective. The first mining wait was too short for the real 0.5/s rate; the continuation used a rate-derived deadline and passed.
- Transfers: three load/take/reopen cycles and three split/merge cycles conserved stock. Quantity selection and splitting used UI events; merges used the inventory drag/drop command seam. Focused transfer tests also cover full-backpack refusal, capacity and stale destinations. This is not an exhaustive all-items/all-slots certification.
- Crafting: UI Craft and Cancel refunded ingredients; completed handcraft produced ten individual bullets. Rifle crafting created one instance. A **Toolkit pointer drag** from Backpack to HUD slot 9 retained its identity. Actual key 9 equipped it; R loaded those ten bullets, leaving zero reserve. Clicking the inventory UI did not fire it.
- Build assignment through Toolkit submit swapped existing shortcuts without duplication or material consumption. Machine E interaction, recipe selection and save serialisation/deserialisation preserved the recipe and cleared stale pairing. Existing player save files were not overwritten; evidence snapshots were written only under this report's evidence folder.
- Menus: Save/Load/Settings/Back/Resume navigation, paused digit/R isolation, unavailable audio messaging and notice-burst priority passed. Menu Save was inspected without committing a new player save. Interface scale was exercised through Settings and restored to 100%.
- Visual: 1080p, 720p and 720p/125%; expanded objective, recipe density, edge tooltip, input contrast, live mining and changed camera framing. No user-facing camera zoom control was added.

The editor was returned to World + GameUI in edit mode, 1920×1080, interface scale 100%, with its original input-focus settings.

**Limits:** Unity's Game View was unfocused. Queued Input System events drove world actions; UI used Toolkit pointer or submit events. At enlarged scale the synthetic pointer helper missed a Build button, whose submit path passed. This does **not** certify native OS mouse interaction. No standalone Windows build, full raid/recovery/excursion run, ultrawide matrix, all-machine operating-state exercise or performance certification was performed. World art and audio content remain separate unfinished work; this UI pass does not make the entire port feature-complete. Browser research pages/screenshots are references, not comparative playtests.

Raw records and one-off inspection scripts: [evidence/ux-pass](evidence/ux-pass/). Earlier failed probes remain in their logs with successful corrections/continuations; zero-test filter attempts are not counted as passes.

## Controls and editable locations

| Control | Behaviour |
|---|---|
| Tab / Inventory button | Open or close Backpack |
| B / Build button | Open or close Build |
| 1–9 / 0, or dock click | Select shortcut; assigned owned weapons equip their actual instance |
| LMB | Selected build/weapon action; with Hands, hold on salvage to mine |
| WASD / arrows | Move; no click-to-move |
| E | Interact with the pointed reachable machine or Home target |
| R | Rotate placement/pointed rotatable machine, otherwise reload |
| Escape | Cancel drag/context action, close drawer, clear hand, then pause; pause children return through their existing Back/Escape chain |
| Right-click shortcut | Clear that shortcut |
| Backpack → Workshop | Focus recipe cards; Backpack returns to inventory |

UI Builder entry: `Assets/Relight/UI/GameUI.uxml`. Edit `UI/Hud/Hud.uxml` / `.uss` for the dock and target card, `UI/Inventory/InventoryPanel.*` for the drawer, `UI/Workshop/WorkshopPanel.*` and `RecipeCard.uxml` for crafting, `UI/Build/BuildPanel.*` for construction, `UI/Guide/GoalCard.*` for objectives, and `UI/Styles/tokens.uss` for the shared palette/controls. Runtime data binding lives in the corresponding controllers and `UI/Hud/GameplayDock.cs`; authoritative hover/source rules live in `Sim/Queries/WorldTargetQueries.cs` and `Sim/Campaign/Opening/OpeningQueries.cs`.

## Owner playtest — C-ACC remains pending

1. Start a normal game. Use the objective to gather the missing generator materials, place it, and check the next step makes sense without explanation.
2. Use Tab/B and the visible dock with your mouse; drag an owned weapon onto it, swap shortcuts, reload and fire. Check that clicking or dragging UI never acts on the world.
3. Transfer, split and repeatedly merge stacks, including a rightmost/scrolled slot and a nearly full Backpack. Cancel a craft, complete one and revisit a machine recipe after saving/loading.
4. Try your preferred window and UI scale. Hover a disabled recipe and the last dock slot; expand the goal, open Workshop and type a save name. Report any unreadable, covered or offscreen control.
5. Continue through the introductory defence, resupply, recovery and excursion. Those campaign acceptance steps are still unverified by this pass.
