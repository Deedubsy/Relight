# Migration map — reference systems → Unity

**Purpose.** One traceable entry per system of the reference game: where it lives today, what it does, what it is meant to do if that differs, where it goes in Unity, what it depends on, its disposition, its known defects and the task that carries it. This is the only owner of *disposition* per system. Rules and values live in [GAME_DESIGN.md](GAME_DESIGN.md) and [CONTENT_CATALOGUE.md](CONTENT_CATALOGUE.md); world data in [WORLD_AND_ASSETS.md](WORLD_AND_ASSETS.md); screens in [UI_AND_ONBOARDING.md](UI_AND_ONBOARDING.md); technical rationale for every destination in [TECHNICAL_ARCHITECTURE.md](TECHNICAL_ARCHITECTURE.md); task status only in [TASKS.md](TASKS.md); owner decisions only in [DECISIONS.md](DECISIONS.md).

**Coverage.** Every `.ts` file in `packages/sim/src` (84 root + 11 `city/`), every file in `packages/game/src` (31 `.ts` + `style.css` + `editor/`), and every file in `packages/harness/src` (22 + 16 `experiments/`) and `packages/tools/src` (12) appears in exactly one row's source list: 178 files, counted by `ls` on 2026-09-11 against [SOURCE_INVENTORY.md](SOURCE_INVENTORY.md). Reference paths are relative to `packages/sim/src` (S-01–S-36), `packages/game/src` (S-37–S-51), `packages/harness/src` (S-52–S-60) and `packages/tools/src` (S-61–S-66) unless written in full. Line counts in parentheses are `wc -l` on 2026-09-11.

**Status labels** (in the *Current behaviour* column): **IR** Implemented and retained · **ANI** Approved but not implemented · **INC** Implemented but needs correction · **UNR** Unresolved · **RET** Retired.
**Disposition:** Port (translate faithfully) · Adapt (same purpose, new mechanism) · Replace (Unity does it differently) · Retire (does not come across).
**Tasks** column: the TASKS.md rows that implement or retire the system. A defect or INC item names the task that corrects it.

**Owner decisions 2026-09-11.** The owner answered the questions several dispositions were waiting on. Applied in the rows below, each once: **Q01/Q07** no old-save converter, schema clean at v1 (S-05, S-A4, §9); **Q06/Q13/Q15** the full approved gameplay direction is in scope with provisional values (S-19, S-29, S-30, S-34); **Q08** `legacy-v1` and everything reachable only through it are retired with a reason (S-06, S-29, S-31, §8); **Q09** audio is in scope as new content (new row **S-A5**); **Q10** telemetry retired, local diagnostics only, no task inherits a reporting obligation (S-50, §8); **Q11** manual saves plus a rotating autosave ring (S-05, S-37); **Q12** the baseline stays a preserved snapshot (§1); **Q19** desktop keyboard and mouse only (S-40). Where a row previously read "owner decision needed" or "recommendation", it now states the decision. No row was renumbered and no file count changed.

## 9. Old-save import — the facts, and the decision

**Facts.** `SaveFile.version` ∈ {1,2,3} and must equal `state.version` (`save.ts:75`, `:114`). `CampaignState.version` ∈ 1…10 (`rules.ts:13`), with further orthogonal sub-versions (`expansion.surveyVersion` 2|3, `defence.version`, `authored.version` 4, `flow.ammoVersion`, `flow.version`). `loadState` runs **18** `init*`/`migrate*` upgraders in a fixed order and re-validates through **31** chained `*Problem` functions. Eight renderer-side upgrade flags (`session.ts:106-118`) do not block loading — they only clear `logComplete`. A save from an earlier authored city id is **rejected outright** by `authoredProblem`. All saves in the repository are fixtures or internal playtest evidence; there are no external players.

**Recommendation (Worker B, adopted as U-M-06).** Do not port `SaveFile` v1–3 into Unity; start a fresh versioned Unity save format and preserve every reference save byte-for-byte as read-only verification fixtures. Reproducing 18 migrators and 31 validators against JS value semantics (sparse `Record` maps, `undefined`-vs-absent keys, JSON number canonicalisation) to keep `stateHash` stable is a large, permanent cost for content no player holds, and the project's own precedent (`authoredProblem`, `CLAUDE.md` CITY-D handoff) is already preserve-plus-New-Game rather than migrate.

**Owner decision — answered 2026-09-11 (Q01/Q07).** The owner starts fresh in Unity; existing saves stay with the original game, which still runs. **No old-save converter is required**, conversion is removed from every completion dependency, and the Unity save schema starts **clean at v1** — no version 0, no compatibility branch, no reader for `SaveFile` v1–3. F-06 closes as **done (not required)** without any work, and no acceptance — including F-ACC — depends on it. The recommendation above is therefore adopted, not merely recorded, and U-Q-01 is closed. *(Correction 2026-09-11: this paragraph previously described "a recorded default" that the owner might overturn; the owner has now answered.)* Preservation of the reference saves is unconditional and unaffected — they are provenance, not required fixtures (TECHNICAL_ARCHITECTURE.md §9.3, S-A4).
