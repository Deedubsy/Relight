# Decisions — Unity migration

This file is the migration's decision record. It holds three kinds of entry, kept apart:

- **Confirmed owner decisions** that the Unity port must honour. Each entry names its provenance in the reference project. The reference `docs/DECISIONS.md` and `docs/EXPLORATION_DEFENCE_PLAN.md` §6.3 remain the historical record; this file records what carries over and does not rewrite them.
- **Migration choices** made by the coordinator with justification. These are engineering choices, not gameplay approvals, and the owner can overturn them.
- **Owner questions**, each marked resolved, awaiting external information, or deferred to the phase where it becomes answerable (§4). One remains open: U-Q-04 (the art package and tileset licence). U-Q-02 (the ending) was resolved on 2026-09-20 by U-D-60.

Status labels used across the package: **Implemented and retained** / **Approved but not implemented** / **Implemented but needs correction** / **Unresolved** / **Retired**. Numbers are tagged **current** (in code today), **approved** (explicitly confirmed by the owner) or **provisional** (chosen for the checkpoint, may change).

Related: [GAME_DESIGN.md](GAME_DESIGN.md) for the experience these decisions shape, [CONTENT_CATALOGUE.md](CONTENT_CATALOGUE.md) for the values, [MIGRATION_MAP.md](MIGRATION_MAP.md) for per-system disposition, [TASKS.md](TASKS.md) for status.

## Current UI implementation authority — 2026-09-14

The owner explicitly authorised a comprehensive researched UI/UX improvement pass, including Tab for inventory and discretionary UI changes. This supersedes earlier planning-only UI gates for this scope. The pass preserves approved gameplay, opening stock, saves and the authored world; reference games inform interaction/layout choices rather than changing Relight's economy. Focused tests and one bounded integrated UI check are proportionate; no full-suite or campaign-acceptance claim follows. [Implementation rationale and evidence](UI_UX_PASS_2026-09-14.md). C-ACC remains `human`; TASKS owns status.

### U-D-RAID-01 — Raid field reach and origin guard (engineering, 2026-09-19; owner authorised the fix with "Do it. Use gizmos where you can")

A deliberate behaviour difference from the reference. The reference builds the raid distance field inside a 70-tile box measured from the Home core's top-left tile, which worked there because its raid line (`homeRaidY` 391) sat within 70 rows of the core. The Unity court plan (D19) put the raid line on the south ring road at row 432, 72 rows below the core's last row, so the field never reached it, no legal entry tile existed, and `DirectorRules.Origin` fell back to the cheapest interior tile: the introductory attack was born at (62,347), inside the compound, three tiles from the workshop. The port now (a) sizes the field as `RaidField.Reach = EntryFarSteps + 12 = 88` tiles beyond every edge of the core rect, so any raid line within the entry band is inside the field on every map; (b) makes `Origin` skip tiles that are not entry tiles, so an impossible map yields no origin (and no group) rather than an interior one; (c) adds Verify check C20 and `RaidOriginTests`; (d) adds the `Relight/Gizmos/Raid Director` Scene gizmo that draws the field box, entry tiers, raid line, engineer safety ring, approaches and origin. The GAMEPLAY_FUN_AUDIT finding that the major assault "silently vanishes" on this map had the same root cause; Origin and Staging now resolve, but the assault schedule itself was not replayed. Record: `FOUNDERS-COURT-SPAWN-FIX.md`; court decision D54.
